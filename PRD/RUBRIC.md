# 評分 Rubric v1.1.0（Mock 模式）

> 對應 `GOAL.md` AC-005、`PRD/SPEC.md` FR-003。實作：`app/lib/scoring/rubric.ts`；測試：`tests/unit/rubric.test.ts`。
> 本文件與程式必須同步；修改任一邊時要同時修改另一邊並升版 `RUBRIC_VERSION`。

## 1. 原則

1. **可重現**：純函式，不使用亂數、時間或任何外部狀態。同樣的回答與題目必得同樣的分數與回饋。
2. **只觀察使用者自己寫的回答**：不補寫、不推測、不捏造任何經歷；空白回答一律 0 分。
3. **證據與建議分開**：
   - `evidence`（可觀察的證據）：從回答文字中實際偵測到的事實，例如長度、STAR 關鍵詞、數字。
   - `suggestions`（建議）：下一步可以怎麼改；只給方向，不替使用者撰寫答案，最後一則固定提醒「請用自己的話」。
4. **這是關鍵詞與格式規則，不是語意理解**。分數只代表「回答的形式是否符合 STAR 與量化的寫法」，不代表內容真實性，也不是錄取預測或人格評斷。

## 2. 偵測項目

| 項目 | 偵測方式 |
|---|---|
| 長度 | 長度單位 ＝ 中日韓字元數（漢字、日文假名、韓文）＋ 英文／數字詞數 × 2 |
| 長度區間 | 空白（去除空白字元後沒有任何字元）｜1–29：極短（有內容但長度單位為 0，例如只有標點或表情符號，也算極短）｜30–99：偏短｜100–600：適中｜601–1200：偏長｜>1200：過長 |
| STAR 四要素 | 回答（轉小寫後）是否包含各要素的關鍵詞（比對方式見下方「關鍵詞比對」）。情境：當時、那時、背景、去年、在前公司、when I、last year…；任務：負責、任務、目標、需要、挑戰、my role、the goal…；行動：我先、我決定、我主動、我設計、我協調、I implemented、I led…；結果：結果、最後、最終、成果、提升、降低、縮短、as a result、improved…（完整詞表見 `STAR_LEXICON`） |
| 量化數字 | 阿拉伯數字（可帶單位：%、倍、人、位、天、週、個月、年、萬、元、ms、users…），以及「中文數字＋單位」（例如 三成、兩倍、五位、三個月）。接在「第」後面的序數（第二天、第3天）不算。去重時忽略數字與單位之間的空白（「30 %」與「30%」算同一個）後計數 |
| 不確定語氣 | 可能（「不可能」不算）、大概、也許、好像、或許、不太確定、不知道、maybe、probably、not sure…（`HEDGE_LEXICON`） |
| 第一人稱行動詞 | 行動要素詞表中命中的種類數 |
| 句數 | 以 。！？!? 與換行、英文句點切分 |
| 條理連接詞 | 首先、接著、然後、之後、最後、因此、所以、first、then、finally、because…（`CONNECTIVE_LEXICON`） |
| 題目關鍵詞重疊率 | 題目去除常見題幹用語（請用、STAR、描述、分享、一次、的經驗…）後，中文取相鄰二字、英文取 3 個字母以上的單字；計算有多少比例出現在回答中（比對方式同下）。題目沒有可用關鍵詞時為「無」 |
| 關鍵詞比對 | 英文／數字開頭的詞整詞比對：前後不能緊接英文字母或數字（`handled` 不算命中 `led`，`sometimes` 不算命中 `time`）；中文詞以子字串比對 |

## 3. 五個維度（各 0–100 的整數）

| 維度 | 權重 | 計分規則 |
|---|---:|---|
| `structure` STAR 結構 | 30% | 偵測到的 STAR 要素數 × 25（0／25／50／75／100） |
| `depth` 深度與量化 | 25% | 量化數字：0 處 0 分、1 處 30 分、2 處 45 分、3 處以上 60 分；加上長度區間分：極短 0、偏短 15、適中 40、偏長／過長 30 |
| `relevance` 相關性 | 20% | 30 ＋ 70 × min(1, 重疊率 ÷ 0.3)；題目無可用關鍵詞時為中性 50；極短回答上限 40 |
| `clarity` 表達清晰度 | 15% | 長度區間分：極短 20、偏短 50、適中 80、偏長 65、過長 50；至少 3 句 ＋10；使用條理連接詞 ＋10；極短回答不加分；上限 100 |
| `confidence` 自信程度 | 10% | 40 ＋ 第一人稱行動詞每種 10（最多 ＋40）＋ 有「結果」要素 ＋20 − 不確定語氣每種 10（最多 −30）；極短回答上限 30；範圍 0–100 |

**總分** ＝ 五個維度依權重加總後四捨五入（0–100）。

**空白回答**（去除空白字元後長度為 0）：五個維度與總分皆為 0；`evidence` 只有「回答為空白（0 字）。」；回饋為「未填寫回答。請用自己的話描述一個真實經驗。」

## 4. 回饋內容

- `evidence` 固定依序列出：回答長度與區間 → 偵測到的 STAR 要素（附命中的關鍵詞）→ 未偵測到的 STAR 要素 → 量化數字（最多列 5 個）或「未偵測到量化數字」→ 不確定語氣（如有）→ 題目關鍵詞重疊率（如有）。
- `suggestions` 依偵測結果產生：缺少的 STAR 要素、沒有數字、偏短或偏長、不確定語氣、重疊率低於 10%；最後固定加上「請用自己的話、依自己的真實經驗作答；不要填入沒有發生過的內容。」

## 5. 整場報告（`summarizeAnswers`）

- 總分 ＝ 逐題分數的平均（四捨五入）。每題都有分數時（自備 key 模式由 AI 給分）採用該分數，讓報告開頭的總分與摘要中的平均分一致；否則採用 rubric 分數。
- 雷達圖五維 ＝ 各題 rubric 結果的平均（四捨五入）。
- 強項、待改進只引用統計事實（例如「5 題中有 3 題偵測到完整的 STAR 四要素」「2 題沒有量化數字」），沒有偵測到強項時強項為空，不捏造優點。
- 摘要寫出逐題平均分，並註明雷達圖「依 rubric 的關鍵詞與格式規則計算，非真人或 AI 語意評審」。

## 6. 自備 API key（BYOK）模式

- 分數、五維與建議由 AI 供應商回傳（經 `LlmProvider`），並強制整理為 0–100 的整數。
- **`evidence` 仍一律由本機 rubric 的偵測結果產生**，不採用 AI 的敘述，避免 AI 捏造「證據」。
- 供應商失敗降級時，整題改用本 rubric 評分，回應標示 `degraded: true`。

## 7. 已知限制

- 關鍵詞比對可能誤判（例如回答中剛好出現「結果」二字就算有結果要素；中文沒有詞界，子字串比對仍可能誤中），也看不出回答內容是否真實或合理。
- 相關性只是用詞重疊的粗略指標；用同義詞回答會被低估。
- 目前詞表以繁體中文與英文為主。
